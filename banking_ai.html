Banking AI Customer Assistant

Problem & my implementation

I built a Python/FastAPI prototype that answers employee questions from a fictional banking-policy PDF. The implementation separates document retrieval, model-generated answers, and deterministic human-review rules.

Request flow

  • Prepare source material. Extract PDF text and split it at known policy headings while preserving page numbers.
  • Retrieve context. Lowercase and tokenize the question and policy chunks. Rank shared tokens using inverse-document-frequency-style weights, normalize by question length, apply a minimum score of 0.05, and return at most two chunks.
  • Generate a typed answer. Pass retrieved text to the OpenAI Responses API and parse it into a Pydantic model containing answer and source. When retrieval produces no context, return a fixed unavailable-information response without a model call.
  • Route sensitive cases. Python rules flag phrases such as “without permission” and “charged twice,” or a missing source, for human review. The model does not decide that flag. POST /ask returns the answer, source, top retrieved page, and review flag.

Design tradeoffs

The current retrieval code uses weighted keyword overlap, not FAISS or embeddings. It is simple to inspect but can miss paraphrases and can retrieve irrelevant text that shares common words. The score is not a calibrated confidence estimate. The returned page belongs to the top retrieval result; it is not independent proof that every generated statement is supported.

Evidence & validation

Retrieval implementation · Structured generation · API and review rules

The repository includes retrieval, routing, and response-field tests. Some retrieval tests still call the previous embedding-based function signatures and need updating to match the current implementation. I am not presenting the older README accuracy figures as current results.

Next engineering step

Update the regression tests and evaluate paraphrases, unsupported questions, and sensitive requests against a labeled dataset. Compare lexical retrieval with embeddings using the same questions before claiming improved retrieval quality. This prototype uses fictional policies and does not make banking decisions.
