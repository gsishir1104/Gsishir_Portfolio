Remnants / CHRONOS Character Lab

Problem & my implementation

A mystery-game NPC should respond to the player while remaining consistent with the story and leaving player movement under player control. This prototype connects Unity C# character state to a Flask server, with rule-based story events and Ollama-generated conversation.

How it works

  • Story-event integration. AICharacterClient subscribes to StoryEventManager.EventRaised in OnEnable and unsubscribes in OnDisable. It records the event in character memory, skips AI control for the playable character, and posts NPC state as JSON using UnityWebRequest.
  • Separate events from conversation. /character_reaction chooses authored reactions in Python. For conversation, fixed story replies are checked first; other Varun questions call Ollama’s gemma3:4b model.
  • Bounded context. The Varun prompt includes explicit known story facts, a current goal, up to 1,400 trailing characters of saved memory, and 1,800 of recent conversation. Selected player topics map to short memory entries through deterministic rules.
  • Fallback behavior. Failed Unity requests use local event reactions. Server-side conversation catches selected network and response errors and returns authored dialogue. A phrase filter rejects certain invented destinations and outdated story references.

What this demonstrates

Application-level model integration, separation of game events from generated dialogue, bounded context, and a playable fallback path. It uses an existing local model; I did not train the language model.

Limitations & evidence

Prompt rules and a phrase blacklist do not guarantee story consistency or prevent every invented fact. Local inference can be slow; the server allows a 90-second request timeout. A repeatable dialogue evaluation and stronger structured fact validation are next steps, not completed results.
