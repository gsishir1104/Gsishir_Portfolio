KathhaVerse

Problem & my role

Writers need feedback on a particular chapter revision without exposing private notes or future story information. I worked on the Python/FastAPI backend, database design, AI integration, access controls, tests, and deployment. Akshaya Baitinti led frontend development, responsive interfaces, story visualization, and API integration.

What I implemented

  • Structured chapter analysis. The server splits manuscript text into numbered passages and asks the model for typed entities, relationships, chapter facts, and reader questions. Pydantic validates the response. The server resolves cited IDs back to exact manuscript passages instead of accepting model-written quotations.
  • Writer approval before release. AI interpretations start as pending. Writers review them before verifying a snapshot; a release binds a reader to that snapshot. Later draft edits do not silently change the manuscript the reader was given.
  • Private reading boundaries. Server-side role, ownership, and invitation checks control access. Reader-question generation receives filtered story state and eligible prior answers, rather than unrestricted writer data.
  • Provider and error handling. A server-side gateway supports OpenAI and optional Ollama. It validates structured responses, reports provider errors, restores request allowance after failures, and records operational status and token counts.

Why these decisions matter

A schema can check an output’s structure but cannot establish that an interpretation is true. Exact passage references make suggestions inspectable; writer review decides whether to accept them. Snapshot-based releases also keep feedback attached to the version that produced it.

Evidence & validation

AI gateway and citation resolution · Integration tests

The checked-in tests assert that fabricated quotations are rejected, released snapshots survive later edits unchanged, revoked readers lose access, and later-chapter answers do not enter earlier-chapter memory. These are code-level test examples, not a claim that a fresh test run was performed for this portfolio.

Current limits

AI interpretations still need review. Reader Memory uses database retrieval; it is not an embedding search system. Prediction matching uses exact phrases rather than semantic correctness scoring. AI requests are synchronous, so durable background processing is a future improvement.
